# PowderScope

Локальная демонстрация детекции порошковых частиц (`models/best_yolo26.pt`, YOLO26s)
и классификации их покрытия (`models/bestClassifier.pt`, ResNet18).
Backend — FastAPI + Ultralytics + torchvision, frontend — HTML/CSS/JavaScript без Node.js и сборки.
Один сервер обслуживает интерфейс и API.

## Запуск в Windows / PowerShell

Требуется Python 3.10 или 3.11. Из корня проекта:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Откройте **http://127.0.0.1:8000**. Документация API: **http://127.0.0.1:8000/docs**.
Остановить сервер: `Ctrl+C`. Для разработки можно добавить `--reload`.
Запускайте один worker: каждый процесс загружает отдельную копию модели.

Веса должны находиться в `models/best_yolo26.pt` и `models/bestClassifier.pt` (папка моделей исключена из Git).
При отсутствии CUDA используется CPU. Для GPU установите совместимую с видеокартой версию PyTorch;
корневой `requirements.txt` содержит исходное окружение обучения с CUDA 12.8 и зависимости API.
Для запуска демонстрации достаточно `backend/requirements.txt`; Jupyter не нужен.

Необязательные настройки через переменные окружения:

```powershell
$env:MODEL_PATH = 'models/best_yolo26.pt' # Относительно корня проекта или абсолютный путь
$env:CLASSIFIER_PATH = 'models/bestClassifier.pt'
$env:MODEL_DEVICE = 'cpu'               # auto (по умолчанию), cpu или cuda:0
.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Обе модели загружаются при старте, без скачивания других весов. Если загрузка одной из них не удалась,
интерфейс остаётся доступен, `/api/health` возвращает 503 и описание ошибки.
Подробности выводятся в журнал сервера; после исправления настроек перезапустите сервер.

## Использование

1. Выберите или перетащите микроснимок: JPEG, PNG, WEBP, BMP или однокадровый TIFF.
2. Нажмите «Распознать частицы».
3. Посмотрите цветные рамки, количество покрытых, непокрытых и спорных частиц, долю покрытых и среднюю уверенность классификатора. Можно переключить оригинал и результат, скачать размеченное изображение.

Цвета и подсчёт:

| Цвет | Группа | Условие |
|---|---|---|
| Зелёный | Покрытые | `coated`, уверенность классификатора ≥ 70% |
| Бледно-красный | Непокрытые / недостаточное покрытие | `insufficient_coating`, уверенность ≥ 70% |
| Жёлтый | Спорные | Максимальная вероятность классификатора < 70% |

Три группы не пересекаются, их сумма равна числу найденных частиц.
`Покрытие = покрытые / все найденные × 100%`. Спорные входят только в знаменатель,
поэтому показатель описывает долю **уверенно покрытых** частиц. После ручной оценки в число
покрытых включаются и частицы, отмеченные пользователем. Если частиц нет, показывается «—».
Это процент частиц, а не процент площади белого слоя: маски сегментации отсутствуют.
Степень частичного покрытия определяется обученным классификатором; второй класс включает
как недостаточное, так и отсутствующее покрытие.

На результате отображаются только рамки. Номер частицы появляется при наведении на её
область, включая увеличенное изображение. В режиме оригинала подсказки скрыты.
Скачиваемое изображение также содержит только рамки, без номеров и процентов уверенности.

Переключатели «Покрытые», «Спорные», «Непокрытые» управляют видимостью рамок на изображении.
Можно оставить одну или несколько групп либо скрыть все рамки. Исходное изображение остаётся
видимым; скрытые рамки не участвуют в наведении и выборе кликом. «Показано: X из Y» показывает
число видимых рамок, а общая сводка всегда считается по всем найденным частицам.

Клик по рамке или области найденной частицы открывает крупный план с контекстом 10%, текущий
класс и исходную уверенность классификатора. Выбрать частицу можно также через список
«Открыть частицу…», в том числе если рамки перекрываются. В окне просмотра доступны переходы
к предыдущей/следующей видимой частице; закрытие — крестиком, Escape или кликом снаружи окна.

Для исходно спорной частицы доступны кнопки «Покрыта» и «Непокрыта». Ручной выбор изменяет
цвет рамки, группу в фильтрах, счётчики и процент покрытия. Его можно заменить или отменить;
исходные вероятности и класс модели сохраняются отдельно. Если новая группа скрыта фильтром,
рамка исчезнет с общего изображения, но окно частицы останется открытым для проверки и отмены.
Скачивание учитывает текущие фильтры и ручные решения, независимо от выбранного масштаба.
Правки хранятся в памяти страницы до обновления, загрузки другого файла или повторного анализа;
API по-прежнему возвращает исходный результат моделей, без ручных правок.

Изображение можно приближать колесом мыши или кнопками `−` / `+` до 800% от масштаба
вписанного изображения. Перетаскивание перемещает увеличенный снимок; двойной щелчок по свободной области
переключает увеличение 200% и полный вид, «Сбросить» возвращает полный вид.
Масштаб сохраняется при переключении оригинала и результата и сбрасывается при загрузке
другого файла. На телефоне доступны кнопки и перемещение пальцем.
Клавиатура: перейдите к изображению клавишей Tab, используйте `+` / `−`, стрелки для
перемещения и `0` / `Escape` для сброса.

Средняя уверенность классификации — среднее арифметическое `classifier_confidence` найденных частиц,
выраженное в процентах. Если обнаружений нет, показывается «—».
Это не precision/recall или mAP: для этих метрик требуется эталонная разметка.

На вход подаётся только изображение. Порог уверенности 25% и размер входа 1024 px
заданы на сервере в `backend/config.py`. Там же находится `classifier_confidence_threshold=0.70` —
порог спорных частиц (используется уверенность классификатора, а не детектора).
На вход API по-прежнему подаётся только файл. Фильтры отображения и ручная проверка работают в браузере.

### Подготовка кропов для ResNet18

После детекции для каждой рамки вырезается кроп с контекстом по 10% ширины/высоты с каждой стороны,
с обрезкой по границам изображения. Далее повторяется подготовка при обучении:

1. RGB без CLAHE (`preprocessing=raw`).
2. `ImageOps.pad` до 320×320 с сохранением пропорций, BICUBIC; цвет полей — медиана RGB-пикселей границы кропа.
3. `ToTensor()` (RGB / 255), затем `Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])`.
4. ResNet18 с `Linear(512, 2)`, `eval()` и `inference_mode()`, затем softmax и argmax.

Порядок вероятностей: `[p_coated, p_insufficient]`. Размер и padding читаются из checkpoint;
нормализация по умолчанию — ImageNet, как при обучении этого файла. Для другого совместимого
checkpoint без нормализации есть переменная `CLASSIFIER_NORMALIZATION=none`; для текущего оставьте
`imagenet`. Кропы обрабатываются пакетами по 16, без накопления всех тензоров в памяти.

Лимиты: 20 МБ, 25 миллионов пикселей, до 1000 детекций на изображение. При достижении лимита
интерфейс показывает предупреждение. Изображения и результаты не сохраняются приложением на диск;
они обрабатываются в памяти. Загрузчик multipart может временно буферизовать большие файлы
в системной временной папке; файл закрывается после запроса.

TIFF преобразуется сервером в RGB и становится доступен для просмотра после анализа.
Предпросмотр и скачиваемая разметка возвращаются в JPEG, исходный файл не изменяется.
EXIF-поворот применяется до анализа, поэтому координаты соответствуют изображению на экране.

Размеры рамок в ответе API указаны в пикселях, а не в физических единицах.
Для перевода в мкм нужна калибровка масштаба. Уверенность модели не является оценкой точности
на ваших данных. При нуле обнаружений можно попробовать другой снимок.
Первый инференс включает инициализацию predictor и может быть заметно медленнее следующих.

## API

### `GET /api/health`

Возвращает состояние цепочки (`ready` / `unavailable`), обе модели, `classifier_ready`, устройство,
классы, ограничения, `classifier_confidence_threshold` и `classifier_normalization`.
HTTP 200 — обе модели загружены, HTTP 503 — хотя бы одна недоступна; результаты без классификации не возвращаются.

### `POST /api/predict`

Тело `multipart/form-data`:

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `file` | file | — | Изображение, обязательное поле |

Пример из PowerShell (`curl.exe`, чтобы избежать алиаса `curl`):

```powershell
curl.exe -X POST http://127.0.0.1:8000/api/predict -F 'file=@C:/images/powder.png' -o result.json
```

Ответ содержит `image` (имя, ширина, высота), `statistics`, `detections`, параметры модели,
устройство, `inference_ms`, `detector_inference_ms`, `classifier_inference_ms`, `total_ms` и два изображения JPEG как base64 data URL:
`original_image`, `annotated_image`. Время не включает передачу по сети; `total_ms` включает
декодирование, инференс и подготовку изображений. Подробные метаданные и детекции
доступны через API; интерфейс показывает изображение, сводку по покрытию и среднюю уверенность классификатора.

Каждая детекция: `id`, `class_id`, `class_name`, `confidence`,
`bbox: [x1, y1, x2, y2]`, `width_px`, `height_px`. Рамки отсортированы по убыванию уверенности.
Координаты относятся к оригиналу после EXIF-поворота, начало координат — левый верхний угол.

Также каждая детекция содержит `coating_class` (`coated` / `insufficient_coating`),
`p_coated`, `p_insufficient`, `classifier_confidence` и итоговый `coating_status`
(`coated` / `uncoated` / `uncertain`). Аргмакс-класс сохраняется и для спорной частицы.
`confidence` по-прежнему относится к детектору. В ответе дополнительно передаются имя
`classifier`, `classifier_confidence_threshold` и `classifier_normalization`.

В `statistics`: `count`, `coated_count`, `uncoated_count`, `uncertain_count`, `coverage_percent`,
`mean_classifier_confidence`, `mean_confidence` (детектор), средние размеры рамок и флаг достижения лимита.

Ошибки: 400 — файл пуст/повреждён или формат не поддержан; 413 — превышен размер;
422 — отсутствует файл; 429 — модель занята (один инференс одновременно);
503 — одна из моделей не загружена; 500 — сбой детекции/классификации. Текст находится в `detail`.
Отдельный frontend-сервер не требуется: запросы идут на тот же origin.

## Проверки

```powershell
.venv\Scripts\python.exe -m pip install httpx
.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
node --check frontend/app.js
node --check frontend/image-viewer.mjs
node --check frontend/particle-review.mjs
node --test frontend/tests/image-viewer.test.mjs frontend/tests/particle-review.test.mjs
```

Тесты проверяют API, вход только с изображением, фиксированные настройки, рамки и статистику, нулевые детекции, ошибки загрузки,
занятость модели, лимиты, TIFF и EXIF-поворот. Также проверяются три группы покрытия,
низкая уверенность, контекст кропа, pad с медианным фоном, порядок пакетной классификации,
цвета рамок и недоступность классификатора. Для API-тестов используется тестовый predictor;
качество распознавания следует проверять отдельно на размеченной выборке микроснимков.
Тесты просмотра проверяют вписывание изображения, масштабирование относительно курсора,
ограничение перемещения, выбор по координатам и сброс масштаба. Тесты ручной проверки покрывают
фильтрацию одной/нескольких групп, изменение и отмену решения, пересчёт статистики,
сохранение исходного результата модели, границы крупного плана и цвет видимых рамок.
`frontend/package.json` используется только для
модулей и запуска тестов; сборка и установка npm-зависимостей не нужны.

## Структура

```text
backend/           API, конфигурация, инференс, тесты
frontend/          интерфейс, стили, загрузка и скачивание изображения
models/            best_yolo26.pt, bestClassifier.pt (локальные веса)
research/          notebooks подготовки данных и обучения
requirements.txt   исходное окружение обучения + API
```

Используемые API: [Ultralytics Predict](https://docs.ultralytics.com/modes/predict/),
[FastAPI UploadFile](https://fastapi.tiangolo.com/tutorial/request-files/),
[FastAPI StaticFiles](https://fastapi.tiangolo.com/tutorial/static-files/),
[torchvision ResNet18](https://docs.pytorch.org/vision/main/models/generated/torchvision.models.resnet18.html).
