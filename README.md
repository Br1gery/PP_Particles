# PowderScope

Локальная демонстрация детекции порошковых частиц (`models/best_yolo26.pt`, YOLO26s)
и классификации их покрытия (`models/bestClassifier.pt`, ResNet18).
Backend — FastAPI + Ultralytics + torchvision, frontend — HTML/CSS/JavaScript без Node.js и сборки.
Один сервер обслуживает интерфейс и API.

## Запуск в Windows / PowerShell

Требуется Python 3.10 или 3.11. Из корня проекта:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Откройте **http://127.0.0.1:8000**. Документация API: **http://127.0.0.1:8000/docs**.
Остановить сервер: `Ctrl+C`. Для разработки можно добавить `--reload`.
Запускайте один worker: каждый процесс загружает отдельную копию модели.

Веса должны находиться в `models/best_yolo26.pt` и `models/bestClassifier.pt` (папка моделей исключена из Git).
При отсутствии CUDA используется CPU. Для GPU установите совместимую с видеокартой версию PyTorch;
корневой `requirements.txt` содержит исходное окружение обучения с CUDA 12.8 и зависимости API.
Для запуска демонстрации достаточно `backend/requirements.txt`; Jupyter не нужен.

Необязательные настройки через переменные окружения:

```powershell
$env:MODEL_PATH = 'models/best_yolo26.pt' # Относительно корня проекта или абсолютный путь
$env:CLASSIFIER_PATH = 'models/bestClassifier.pt'
$env:MODEL_DEVICE = 'cpu'               # auto (по умолчанию), cpu или cuda:0
.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Обе модели загружаются при старте, без скачивания других весов. Если загрузка одной из них не удалась,
интерфейс остаётся доступен, `/api/health` возвращает 503 и описание ошибки.
Подробности выводятся в журнал сервера; после исправления настроек перезапустите сервер.

## Использование

1. Выберите или перетащите микроснимок: JPEG, PNG, WEBP, BMP или однокадровый TIFF.
2. Нажмите «Распознать частицы».
3. Посмотрите цветные рамки, количество покрытых, непокрытых и спорных частиц, долю покрытых и среднюю уверенность классификатора. Можно переключить оригинал и результат, скачать размеченное изображение.

Цвета и подсчёт:

| Цвет | Группа | Условие |
|---|---|---|
| Зелёный | Покрытые | `coated`, уверенность классификатора ≥ 70% |
| Бледно-красный | Непокрытые / недостаточное покрытие | `insufficient_coating`, уверенность ≥ 70% |
| Жёлтый | Спорные | Максимальная вероятность классификатора < 70% |

Три группы не пересекаются, их сумма равна числу найденных частиц.
`Покрытие = покрытые / все найденные × 100%`. Спорные входят только в знаменатель,
поэтому показатель описывает долю **уверенно покрытых** частиц. После ручной оценки в число
покрытых включаются и частицы, отмеченные пользователем. Если частиц нет, показывается «—».
Это процент частиц, а не процент площади белого слоя: маски сегментации отсутствуют.
Степень частичного покрытия определяется обученным классификатором; второй класс включает
как недостаточное, так и отсутствующее покрытие.

На результате отображаются только рамки. Номер частицы появляется при наведении на её
область, включая увеличенное изображение. В режиме оригинала подсказки скрыты.
Скачиваемое изображение также содержит только рамки, без номеров и процентов уверенности.

Переключатели «Покрытые», «Спорные», «Непокрытые» управляют видимостью рамок на изображении.
Можно оставить одну или несколько групп либо скрыть все рамки. Исходное изображение остаётся
видимым; скрытые рамки не участвуют в наведении и выборе кликом. «Показано: X из Y» показывает
число видимых рамок, а общая сводка всегда считается по всем найденным частицам.

Клик по рамке или области найденной частицы открывает крупный план с контекстом 10%, текущий
класс и исходную уверенность классификатора. Выбрать частицу можно также через список
«Открыть частицу…», в том числе если рамки перекрываются. В окне просмотра доступны переходы
к предыдущей/следующей видимой частице; закрытие — крестиком, Escape или кликом снаружи окна.

Для исходно спорной частицы доступны кнопки «Покрыта» и «Непокрыта». Ручной выбор изменяет
цвет рамки, группу в фильтрах, счётчики и процент покрытия. Его можно заменить или отменить;
исходные вероятности и класс модели сохраняются отдельно. Если новая группа скрыта фильтром,
рамка исчезнет с общего изображения, но окно частицы останется открытым для проверки и отмены.
Скачивание учитывает текущие фильтры и ручные решения, независимо от выбранного масштаба.
Правки хранятся в памяти страницы до обновления, загрузки другого файла или повторного анализа;
API по-прежнему возвращает исходный результат моделей, без ручных правок.

### Ручные выделения и удаление

После анализа нажмите «Выделить частицу» и обведите её на изображении перетаскиванием.
Координаты учитывают текущий масштаб и перемещение; рамку можно рисовать в любом направлении.
Затем в открывшемся окне выберите «Покрыта», «Непокрыта» или «Спорная».
Новой рамке первоначально назначается класс «Спорная»; уверенность и вероятности модели
для неё отсутствуют. Сводка и процент покрытия учитывают добавленные вручную частицы.
Escape или повторное нажатие кнопки отменяют режим рисования.

В окне любой частицы есть кнопка «Удалить выделение» — для рамок модели и ручных рамок.
Удалённая частица исключается из изображения, списка, статистики, скачивания и отчёта.
«Отменить удаление» восстанавливает последнее удалённое выделение вместе с его классом.
Идентификаторы остальных частиц сохраняются, а новые номера не переиспользуются.

### PDF-отчёт

Кнопка «Сформировать отчёт» скачивает PDF со сводкой, изображением с цветными рамками
и таблицей частиц: номер, класс, источник оценки, исходная уверенность классификатора,
координаты и размеры. Кириллица отображается встроенным шрифтом DejaVu Sans из matplotlib.
Отчёт фиксирует текущие ручные решения и удаления, число исходных обнаружений, добавлений
и удалений. Он включает **все оставшиеся** частицы, даже если их рамки скрыты фильтром.
При большом числе частиц таблица переносится на следующие страницы с повторением заголовка.
Уверенность ручных рамок в таблице обозначена «-», а не вымышленными 100%.
PDF формируется в памяти сервера; перезапуск моделей для этого не требуется.

Изображение можно приближать колесом мыши или кнопками `−` / `+` до 800% от масштаба
вписанного изображения. Перетаскивание перемещает увеличенный снимок; двойной щелчок по свободной области
переключает увеличение 200% и полный вид, «Сбросить» возвращает полный вид.
Масштаб сохраняется при переключении оригинала и результата и сбрасывается при загрузке
другого файла. На телефоне доступны кнопки и перемещение пальцем.
Клавиатура: перейдите к изображению клавишей Tab, используйте `+` / `−`, стрелки для
перемещения и `0` / `Escape` для сброса.

Средняя уверенность классификации — среднее арифметическое `classifier_confidence` найденных частиц,
выраженное в процентах. Если обнаружений нет, показывается «—».
Это не precision/recall или mAP: для этих метрик требуется эталонная разметка.

На вход подаётся только изображение. Порог уверенности 25% и размер входа 1024 px
заданы на сервере в `backend/config.py`. Там же находится `classifier_confidence_threshold=0.70` —
порог спорных частиц (используется уверенность классификатора, а не детектора).
На вход API по-прежнему подаётся только файл. Фильтры отображения и ручная проверка работают в браузере.

### Подготовка кропов для ResNet18

Перед классификацией backend удаляет дублирующиеся рамки с помощью
[torchvision NMS](https://docs.pytorch.org/vision/stable/generated/torchvision.ops.nms.html).
Рамки сначала обрезаются по границам изображения, затем сравниваются по IoU (площадь
пересечения / площадь объединения). При IoU > 0.70 остаётся рамка с большей исходной
уверенностью **детектора**, до округления значений для ответа API. Порог задаётся через
`duplicate_iou_threshold` в `backend/config.py`; параметры входного API не меняются.
Обычное частичное пересечение соседних рамок само по себе не удаляет частицу.
Кропы, классификация, номера, статистика и изображения формируются только для оставшихся
рамок, поэтому дубликаты не увеличивают число покрытых/непокрытых/спорных частиц.
Флаг лимита детектора относится к числу кандидатов до NMS: он сохраняется и при удалении дубликатов.

После детекции для каждой рамки вырезается кроп с контекстом по 10% ширины/высоты с каждой стороны,
с обрезкой по границам изображения. Далее повторяется подготовка при обучении:

1. RGB без CLAHE (`preprocessing=raw`).
2. `ImageOps.pad` до 320×320 с сохранением пропорций, BICUBIC; цвет полей — медиана RGB-пикселей границы кропа.
3. `ToTensor()` (RGB / 255), затем `Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])`.
4. ResNet18 с `Linear(512, 2)`, `eval()` и `inference_mode()`, затем softmax и argmax.

Порядок вероятностей: `[p_coated, p_insufficient]`. Размер и padding читаются из checkpoint;
нормализация по умолчанию — ImageNet, как при обучении этого файла. Для другого совместимого
checkpoint без нормализации есть переменная `CLASSIFIER_NORMALIZATION=none`; для текущего оставьте
`imagenet`. Кропы обрабатываются пакетами по 16, без накопления всех тензоров в памяти.

Лимиты: 20 МБ, 25 миллионов пикселей, до 1000 детекций на изображение. При достижении лимита
интерфейс показывает предупреждение. Изображения и результаты не сохраняются приложением на диск сервера;
они обрабатываются в памяти. Загрузчик multipart может временно буферизовать большие файлы
в системной временной папке; файл закрывается после запроса.

TIFF преобразуется сервером в RGB и становится доступен для просмотра после анализа.
Предпросмотр и скачиваемая разметка возвращаются в JPEG, исходный файл не изменяется.
EXIF-поворот применяется до анализа, поэтому координаты соответствуют изображению на экране.

Размеры рамок в ответе API указаны в пикселях, а не в физических единицах.
Для перевода в мкм нужна калибровка масштаба. Уверенность модели не является оценкой точности
на ваших данных. При нуле обнаружений можно попробовать другой снимок.
Первый инференс включает инициализацию predictor и может быть заметно медленнее следующих.

## API

### Анализ округлости

На странице выберите **«Округлость»**, загрузите снимок и нажмите «Распознать частицы».
Модель сегментации загружается один раз при запуске процесса из `models/particle_yolo26.pt`.
Используется именно содержимое этого файла; путь можно изменить через `SHAPE_MODEL_PATH`.
При замене весов перезапустите сервер. API возвращает SHA-256 реально загруженного checkpoint,
его классы и источник классификации; если файл заменён после запуска, модель помечается
недоступной с явным требованием перезапуска, чтобы не выдавать старые веса за новые.
Её готовность не зависит от моделей покрытия: переключение режимов проверяет соответствующую цепочку.
Вход обоих режимов — только файл изображения, без дополнительных параметров.

Настройки нового режима в `backend/config.py`: размер 640, уверенность обнаружения 0.06,
NMS по рамкам с IoU 0.70. В установленном Ultralytics 8.4.24 явно используется `end2end=False`
(ветка one-to-many с NMS, выбранная до первого инференса). Дополнительный NMS удаляет дубли
между обеими группами, сохраняя класс, контур и исходную уверенность оставшегося обнаружения.
На вход модели подаётся
изображение в градациях серого (три одинаковых RGB-канала). EXIF применяется до анализа.
Нижняя подпись автоматически не обрезается: `footer_cropped=false`. Если подпись/линейка
мешает анализу, подготовьте снимок без неё перед загрузкой.

Для каждого контура рассчитываются площадь `A`, замкнутый периметр `P`, круглость
`C = 4πA / P²`, эквивалентный диаметр `sqrt(4A/π)`, центр масс и ограничивающий прямоугольник.
Геометрия рассчитывается OpenCV по отображаемым контурам, извлечённым из бинарных `result.masks.data`.
Рамка или аппроксимирующая окружность не подменяют маску частицы.
Для каждого обнаружения выбирается внешний контур наибольшей площади. Мелкие раздельные
островки той же маски отбрасываются; они не соединяются с частицей диагональными линиями.
Стандартное объединение раздельных контуров в `masks.xy` здесь не используется.
Один и тот же очищенный контур применяется для измерений, клика, изображения и PDF.
После NMS сравниваются пересечения оставшихся масок. В спорной области предпочтение
получает маска, у которой этот пиксель лежит глубже в основной области относительно её
максимальной толщины; уверенность YOLO разрешает равные оценки. Удаляется только тонкая
периферия захватывающей маски (до 15% нормированной толщины), а её основная область сохраняется.
После такого разделения у `rounded` морфологическое раскрытие убирает оставшиеся узкие
петли контакта. Маски без пересечений этот шаг не меняет; для `irregular` раскрытие не применяется.
Общее уменьшение площади после всех шагов ограничено 12%; при превышении изменение отклоняется.
Для обученного класса `rounded` дополнительно проверяются малые присоединённые выступы:
эрозия разрывает узкую перемычку, после чего восстанавливается основная область в пределах
исходной маски. Выбирается минимальный сработавший радиус; удаление ограничено 12% площади
и применяется только к заметно удалённому выступу. Эта отдельная проверка не применяется
к классу `irregular` и частицам у границы; крупные присоединённые области не удаляются.
Это консервативная эвристика очистки, а не новый результат нейросети и не подгонка к окружности.
В API передаются `contour_refined`, `contour_refinement` (`overlap`, `neck`), `removed_area_percent` и `raw_polygon_px`
(основной контур до этой очистки, только при изменении). В крупном плане показывается
удалённая доля; PDF отмечает число очищенных контуров. Измерения относятся к `polygon_px`.
Ответы `/api/shape/health` и `/api/shape/predict` содержат `contour_processing_version`.
На странице показаны версия обработки и число изменённых контуров. Если версия запущенного
backend устарела относительно интерфейса, анализ блокируется с явным предложением перезапуска.
В режиме разработки запускайте uvicorn с `--reload`, чтобы изменения Python применялись автоматически.
Используется `retina_masks=True`: маски декодируются в разрешение исходного снимка,
а не в сетку уменьшенного входа. Например, для 1280×960 возвращается маска 1280×960
вместо 640×480. Вход нейросети остаётся 640 px; это уменьшает дискретизацию контура,
но не добавляет модели деталей, потерянных при уменьшении входа, и не исправляет её ошибок.
Нативный декодер обрабатывает маски небольшими пакетами, ограничивая промежуточную память.
Если суммарный размер превышает 128 миллионов пикселей масок, сохраняются все обнаружения
с декодированием в уменьшенное разрешение; API и интерфейс явно сообщают об этом через
`mask_quality_warning`. `mask_size` содержит фактические `[высота, ширина]` масок.
Если в checkpoint два класса **`rounded` / `irregular`**, класс и цвет берутся непосредственно
из предсказания обученной YOLO (`boxes.cls`, `model.names`). Круглость измеряется независимо
и не переопределяет предсказанный класс. Для старых весов с единственным классом `particle`
сохранён геометрический режим с порогом **C ≥ 0.80**. Другие наборы классов отклоняются при загрузке.
Округлые показаны зелёным, неокруглые — бледно-красным, частицы у границы — жёлтым.
Касание границы определяется по контуру с допуском один пиксель. Такие частицы исключены
из знаменателя долей и обеих медиан, но включены в общее число. При пустом знаменателе
доли и медианы равны `null` (в интерфейсе «—»). Круглость характеризует двумерный контур,
а не уверенность YOLO и не трёхмерную сферичность; размеры даны в пикселях.

Можно показывать одну или несколько групп, приблизить изображение, открыть отдельную частицу
кликом внутри контура или через список. В крупном плане доступны круглость, площадь, периметр,
диаметр и отдельная уверенность обнаружения. Номер показывается только при наведении.
В режиме «Округлость» доступна ручная разметка после анализа, в том числе если модель не нашла частиц:

- «Выделить частицу» → «Эллипс»: обведите частицу перетаскиванием.
- «Контур по точкам»: кликайте по границе; Enter, первая точка или «Завершить контур» замыкают выделение.
  Backspace / «Убрать точку» отменяет последнюю вершину, Escape отменяет рисование.
  При увеличении изображения Shift + перетаскивание перемещает его, сохраняя начатый контур.
- В окне частицы назначьте «Округлая» или «Неокруглая». Ручной класс имеет приоритет
  над классом YOLO и геометрическим порогом. У границы сохраняется отдельная группа «На границе».
- «Изменить контур» позволяет заново обвести любую частицу выбранным инструментом;
  «Отменить правки» возвращает исходный контур и класс. Любое выделение можно удалить и восстановить.

Площадь, периметр, круглость, диаметр и сводка пересчитываются по текущим контурам.
Эллипс задаёт приближение формы; для точных измерений обводите границу по точкам.
У ручных частиц нет уверенности и класса модели; у исправленных обнаружений исходные
класс и уверенность YOLO сохраняются отдельно. Правки действуют до обновления страницы,
смены изображения/режима или нового анализа. Ручная разметка не переобучает модель.
Лимит — 5000 выделений; ручной контур содержит от 3 до 256 точек, без самопересечений,
с площадью не меньше 4 px². Эллипс представлен 64 вершинами.

Скачивание изображения учитывает фильтры. PDF содержит все оставшиеся контуры, сводку и таблицу
геометрии с источником разметки и уверенностью YOLO, независимо от фильтров. Ручные добавления,
классы и исправления входят в отчёт; удалённые частицы исключаются. Измерения для отчёта
сервер пересчитывает по контурам. Уверенность ручных выделений обозначена «-».

Дополнительные маршруты:

- `GET /api/shape/health`: готовность отдельной модели, устройство, порог круглости, ошибка,
  `model_sha256`, `classes`, `classification_source` (`model | circularity`),
  `inference_mode=nms`, `weights_changed` и `manual_shape_annotations=true`;
  HTTP 200 при готовности, 503 при недоступности.
- `POST /api/shape/predict`: `multipart/form-data`, единственное обязательное поле `file`.
  Ошибки и ограничения загрузки совпадают с `/api/predict`.
  Ответ: `image`, `summary`, `particles`, параметры анализа, `model_sha256`, `classes`,
  `classification_source`, `inference_mode=nms`, `total_ms`, изображения
  `original_image` и `annotated_image` в JPEG data URL и флаг `detection_limit_reached`.
- `POST /api/shape/report`: JSON с `image`, `original_image`, текущим списком `particles`
  (`index`, `confidence`, `class_id`, `class_name`, `polygon_px`, `source`, `manual_form`, `manual_contour`), `model`, `model_sha256`,
  `classification_source` и `timezone_offset_minutes`; возвращает PDF.
  Исходный класс YOLO сохраняется отдельно; `manual_form` имеет приоритет при подсчёте сводки.
  Для ручной частицы `source=manual`, `manual_contour=true`, задан `manual_form`,
  а `confidence`, `class_id`, `class_name` равны `null`. Для исправления контура модели передаются
  новый `polygon_px` и `manual_contour=true`, сохраняя её исходные класс и уверенность.
  Проверяются уникальность номеров, конечные координаты в границах, ненулевая площадь,
  до 5000 частиц и 250000 точек суммарно; ручные контуры проверяются на самопересечения.

В `summary`: `total`, `rounded`, `irregular`, `edge`, `shape_denominator`, `rounded_percent`,
`irregular_percent`, `median_circularity`, `median_equivalent_diameter_px`.
В частице: `index`, `form` (`rounded | irregular | edge`), `class_id`, `class_name`,
`classification_source`, `confidence` YOLO,
`circularity`, `area_px2`, `perimeter_px`, `equivalent_diameter_px`, `centroid_x`, `centroid_y`,
`bbox`, `touches_border`, `polygon_px`. **В этом API bbox = [x, y, ширина, высота]**,
в отличие от xyxy API покрытия. Контур — список `[x, y]` в координатах всего анализируемого снимка.

```powershell
curl.exe -X POST http://127.0.0.1:8000/api/shape/predict -F 'file=@C:/images/powder.png' -o shape-result.json
```

### `GET /api/health`

Возвращает состояние цепочки (`ready` / `unavailable`), обе модели, `classifier_ready`, устройство,
классы, ограничения, `classifier_confidence_threshold` и `classifier_normalization`.
HTTP 200 — обе модели загружены, HTTP 503 — хотя бы одна недоступна; результаты без классификации не возвращаются.

### `POST /api/predict`

Тело `multipart/form-data`:

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `file` | file | — | Изображение, обязательное поле |

Пример из PowerShell (`curl.exe`, чтобы избежать алиаса `curl`):

```powershell
curl.exe -X POST http://127.0.0.1:8000/api/predict -F 'file=@C:/images/powder.png' -o result.json
```

Ответ содержит `image` (имя, ширина, высота), `statistics`, `detections`, параметры модели,
устройство, `inference_ms`, `detector_inference_ms`, `classifier_inference_ms`, `total_ms` и два изображения JPEG как base64 data URL:
`original_image`, `annotated_image`. Время не включает передачу по сети; `total_ms` включает
декодирование, инференс и подготовку изображений. Подробные метаданные и детекции
доступны через API; интерфейс показывает изображение, сводку по покрытию и среднюю уверенность классификатора.

Каждая детекция: `id`, `class_id`, `class_name`, `confidence`,
`bbox: [x1, y1, x2, y2]`, `width_px`, `height_px`. Рамки отсортированы по убыванию уверенности.
Координаты относятся к оригиналу после EXIF-поворота, начало координат — левый верхний угол.

Также каждая детекция содержит `coating_class` (`coated` / `insufficient_coating`),
`p_coated`, `p_insufficient`, `classifier_confidence` и итоговый `coating_status`
(`coated` / `uncoated` / `uncertain`). Аргмакс-класс сохраняется и для спорной частицы.
`confidence` по-прежнему относится к детектору. В ответе дополнительно передаются имя
`classifier`, `classifier_confidence_threshold` и `classifier_normalization`.

В `statistics`: `count`, `coated_count`, `uncoated_count`, `uncertain_count`, `coverage_percent`,
`mean_classifier_confidence`, `mean_confidence` (детектор), средние размеры рамок и флаг достижения лимита.

Ошибки: 400 — файл пуст/повреждён или формат не поддержан; 413 — превышен размер;
422 — отсутствует файл; 429 — модель занята (один инференс одновременно);
503 — одна из моделей не загружена; 500 — сбой детекции/классификации. Текст находится в `detail`.
Отдельный frontend-сервер не требуется: запросы идут на тот же origin.

### `POST /api/report`

Принимает JSON с текущим состоянием разметки:

- `image`: имя файла, исходные `width` и `height`.
- `original_image`: исходное изображение как JPEG/PNG base64 data URL.
- `detections`: все оставшиеся рамки (`id`, `bbox`, `coating_status`, `source: model | manual`,
  исходные вероятности/уверенность и `manual_review` при наличии).
- `initial_detected_count`, `manual_added_count`, `deleted_count`: история количества рамок.
- `model`, `classifier`, `classifier_confidence_threshold`: параметры исходного анализа.
- `timezone_offset_minutes`: смещение `Date.getTimezoneOffset()` для времени отчёта.

Возвращает `application/pdf` с `Content-Disposition: attachment`. Сервер пересчитывает сводку,
проверяет баланс количества рамок, уникальность номеров, границы изображения и отсутствие
выдуманных вероятностей у ручных частиц. Лимит — 5000 текущих выделений.
HTTP 422 означает неверную структуру/несогласованные данные, HTTP 400 — некорректное изображение
или рамку вне его границ, HTTP 500 — ошибку формирования. Фильтры отображения не передаются.

## Проверки

```powershell
.venv\Scripts\python.exe -m pip install -r backend/tests/requirements.txt
.venv\Scripts\python.exe -m unittest discover -s backend/tests -v
node --check frontend/app.js
node --check frontend/image-viewer.mjs
node --check frontend/particle-review.mjs
node --test frontend/tests/image-viewer.test.mjs frontend/tests/particle-review.test.mjs frontend/tests/shape-review.test.mjs
```

Тесты проверяют API, вход только с изображением, фиксированные настройки, рамки и статистику, нулевые детекции, ошибки загрузки,
занятость модели, лимиты, TIFF и EXIF-поворот. Также проверяются три группы покрытия,
низкая уверенность, контекст кропа, pad с медианным фоном, порядок пакетной классификации,
цвета рамок и недоступность классификатора. Для API-тестов используется тестовый predictor;
качество распознавания следует проверять отдельно на размеченной выборке микроснимков.
Тесты просмотра проверяют вписывание изображения, масштабирование относительно курсора,
ограничение перемещения, выбор по координатам и сброс масштаба. Тесты ручной проверки покрывают
фильтрацию одной/нескольких групп, изменение и отмену решения, пересчёт статистики,
сохранение исходного результата модели, границы крупного плана и цвет видимых рамок.
Также проверяются создание ручных рамок без вероятностей модели, выбор их класса,
удаление и восстановление, PDF-таблицы с кириллицей, переносы страниц и проверка данных отчёта.
Тесты разметки формы проверяют эллипсы и полигоны, рисование при увеличении, приоритет ручного
класса, замену и отмену контура, исключение краевых частиц и передачу текущей разметки в PDF.
`frontend/package.json` используется только для
модулей и запуска тестов; сборка и установка npm-зависимостей не нужны.
